# DocuMind candidate ranker model card

## Model

Calibrated logistic classifier over dictionary-encoded candidate features. The serialized artifact is
`candidate_ranker.joblib`, trained with scikit-learn 1.7.2 and joblib 1.5.2.

## Intended use

Rank field candidates for English invoices after PyMuPDF text extraction or Tesseract OCR. It is a
portfolio baseline for local CPU inference, not an autonomous financial decision system.

## Training and evaluation data

- Training: 180 synthetic text-native invoices, seed 17.
- Candidate validation: 30 separate synthetic invoices, seed 1337.
- Layouts, vendor/customer names, currencies, and line items come from the repository generator.
- No real personal, medical, or financial data is included.

## Features

Field identity, label cues, data shape, relative page/line position, OCR confidence, currency/date
indicators, and conflicting subtotal/tax/total cues. Raw vendor or customer identities are not model
features.

## Measured candidate performance

| Metric | Value |
|---|---:|
| Accuracy | 98.60% |
| Precision | 99.75% |
| Recall | 96.37% |
| F1 | 98.03% |
| Brier score | 0.0091 |

See `evaluation/results.md` for end-to-end metrics and commands.

## Limitations

Synthetic calibration can be optimistic and does not establish accuracy on real suppliers, languages,
scan artifacts, or unseen layouts. The model ranks candidates generated by deterministic code, so it
cannot recover a value when candidate generation fails. Line-item extraction remains rule-based.
Human review is required for low-confidence or inconsistent results.
